# V0.2 操作、运维与迁移

## 启动

1. 已安装 Windows 版 Plant Simulation 2606 并具备可签出许可；本机实测 2606.0006，ProgID `Tecnomatix.PlantSimulation.RemoteControl.26.6`。
2. 首次部署执行 `install.cmd`；创建独立 micromamba 环境 `ontologysim-v02`，安装锁定依赖并构建本地前端。
3. 双击 `start.cmd`，打开 `http://127.0.0.1:8820`。首次创建自己的管理员账号。
4. 双击 `stop.cmd` 正常退出，关闭自己的发布器、工作进程和 COM 实例。

安装需要可用软件包源，安装后的运行不依赖 CDN、云服务或 LLM。Plant Simulation 的许可服务仍按本机许可配置工作。

配置：`ONTOLOGYSIM_PORT`（8820）、`ONTOLOGYSIM_OPC_ENDPOINT`（`opc.tcp://127.0.0.1:4843/ontologysim-v2/`）、`ONTOLOGYSIM_PROGID`、`ONTOLOGYSIM_V2_DATA`（项目 `.runtime-v02`）。不要让两个运行实例指向同一数据目录或 OPC 端口。

## 业务操作路径

1. 在生产运行载入柔性机加工工作空间，或在系统管理导入生产配置。准备轨迹是原生任务，完成后开始实际协议接入。
2. 选择一个订单／批次，查看其产品、原料和工件。在产品与工艺查看毛坯 BOM、加工路线、返工路径及逐项设备资格。
3. 点击推进至维护事件，数据源在完整维护观测边界暂停；选择异常查看影响范围及来源。
4. 创建分析基线。此操作本身不暂停数据源。可先继续数据源，再创建基线，看到固定版本与后续现场各自推进。
5. 选择基线运行三方案比较。一次执行一个原生任务；收益由实际结果产生。五组验证是参数样本范围，不是经校准的置信区间。
6. 在运行中暂停或保存，等待事件边界存档出现；可取消。证据页可直接核对恢复、从存档继续运行或打开原生模型窗口。
7. 查看结果表、甘特轨迹和原生核对记录，通过依据抽屉追溯输入版本。上下文下拉可以切换基线、已完成运行和历史空间。
8. 导出证据包，独立保管公钥指纹和回执，使用离线校验器核查。

数据源暂停、仿真暂停和历史回放暂停分别控制。重置会自动归档当前工作空间；原始记录和历史证据保留。

## 主数据修订

系统管理支持订单数量／批量／交期、工序工时／精度／首选设备及设备参数表单修订，也支持完整配置文件导入。点击“校验并查看差异”后查看字段差异、SHACL 结果和影响范围，再发布。发布产生新的工作空间，正在执行任务时拒绝发布，不热改旧批次。

## 备份

正常停止服务后执行：

```powershell
micromamba run -n ontologysim-v02 python -X utf8 -m scripts.v2_backup delivery/workspace-backup.zip
```

备份包含完整工作空间、账号库、已签名历史和 DPAPI 加密私钥，输出必须在数据目录外。完整账号／密钥恢复需原 Windows 用户配置；跨机器迁移分析结果使用不含私钥的证据包。不要复制仍在写入的 RocksDB 目录作为一致性备份。

## V0.1

保留 `v0.1` 标签、`app/` 与 `.runtime`。证据页可只读查看旧项目、结果和存档，明确缺少的责任主体与签名。不将旧 JSON 快照当成 V0.2 可执行本体。

旧生产配置可生成待审查草稿：

```powershell
micromamba run -n ontologysim-v02 python -X utf8 -m scripts.migrate_v01 old-spec.json new-spec-draft.json
```

同时输出 `.migration.json`，列明新增原料批次、重量和质量参数等占位假设。核对并修订后才在工作台校验发布。历史证据不补造。

## 异常处理

- “执行状态待核对”：存在未确认原生命令，不能盲目重试。保留该分支和证据，可选此前已核对的基线重新分析。
- 接入断连：订阅会重连，发布器按已提交游标重传；不完整边界不推进现场。
- 校验问题：数据与语义页展示待处理记录，修订必须保留原始来源。
- 长时间无响应：查看数据目录的 `server.stderr.log` 和系统管理的任务记录；不按进程名批量终止 Plant Simulation。
- 旧开发存档的签名覆盖率可能不完整，核验结果会显示范围；新建正式工作空间启用完整覆盖。

停止服务后也可双击 `backup.cmd`，自动生成带时间戳的新备份。重置时仅在配置、执行程序摘要和已核对轨迹摘要全部一致时复用原生参考轨迹，并从来源游标零重新发布；不复用未经核对或被修改的轨迹。运行 V0.1 请在独立目录检出 `v0.1` 标签并按该版文档构建前端。


## 首次载入与数据源状态

默认车间先核对随附的已验证参考轨迹，随后启动真实 MES HTTP 和 OPC UA 接入。顶部“现场数据已就绪”出现后可推进维护事件。若修改了生产配置或执行模型，需要重新生成参考轨迹；顶部显示实际计算时钟、进度、已用时间和取消入口。

“本轮现场数据已发布完毕”表示有限参考轨迹正常结束，不是连接故障。点击“归档并重新载入”会保留原工作空间和证据，再以同一生产配置创建新现场。出现失败原因时可“重试数据接入”；原生命令状态待核对时禁止盲目重试。

开发验收使用独立端口和数据目录：`python -m scripts.v2_first_load_acceptance --url http://127.0.0.1:8846`。该脚本禁止使用正式端口 8820，会归档并重建指定验收服务的工作空间。
