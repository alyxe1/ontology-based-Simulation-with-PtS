# V0.2 操作、运维与迁移

## 启动

1. 已安装 Windows 版 Plant Simulation 2606 并具备可签出许可；本机实测 2606.0006，ProgID `Tecnomatix.PlantSimulation.RemoteControl.26.6`。
2. 首次部署执行 `install.cmd`；创建独立 micromamba 环境 `ontologysim-v02`，安装锁定依赖并构建本地前端。
3. 双击 `start.cmd`，打开 `http://127.0.0.1:8820`。首次创建自己的管理员账号。
4. 双击 `stop.cmd` 正常退出，关闭自己的发布器、工作进程和 COM 实例。

更新代码后再次运行 `start.cmd` 会核对本机服务加载的版本。服务空闲时会正常重启以加载新代码。正在运行或排队的仿真任务需要先结束。对于升级前启动、尚未提供版本标识的服务，首次更新时运行一次 `stop.cmd` 和 `start.cmd`，再刷新页面。

新登录会话从登录时起有效 30 天，退出登录立即结束该会话。

安装需要可用软件包源，安装后的运行不依赖 CDN、云服务或 LLM。Plant Simulation 的许可服务仍按本机许可配置工作。

可通过环境变量配置本机 HTTP 端口 `ONTOLOGYSIM_PORT`（8820）、`ONTOLOGYSIM_OPC_ENDPOINT`（`opc.tcp://127.0.0.1:4843/ontologysim-v2/`）、`ONTOLOGYSIM_PROGID` 和 `ONTOLOGYSIM_V2_DATA`（项目 `.runtime-v02`）。两个服务实例各用独立的数据目录、HTTP 端口和 OPC UA 端口。

## 业务操作路径

1. 在「生产运行」载入柔性机加工车间，或在「系统管理」导入生产配置。默认配置核对随附参考轨迹后直接接入；自定义配置先完成原生准备任务。
2. 选择一个订单／批次，查看其产品、原料和工件。在产品与工艺查看毛坯 BOM、加工路线、返工路径及逐项设备资格。
3. 点击「推进至下一次维护开始」。发布器逐帧接收确认，停在出现新维护的完整接收帧。同一台设备之后可以再次触发维护。同一次维护的后续观测继续归在原事件中。
4. 在「异常与方案」从维护或检验卡片创建基线，保留异常及影响范围；也可以从当前现场手动创建。基线固定一版已接收的状态，现场继续接入。
5. 选择基线，最多添加 3 个模板或自定义干预。支持 FIFO／EDD、自动改派、等待工件的合格设备指派和全车间班次调整。同批自动加入「保持现状」，沿用基线规则与当前指派。
6. 点击「校验方案」，再点击「查看本体 → 仿真模型映射」检查将要执行的输入。变更方案或样本组后需重新校验。选「快速比较」提交 1 组配对样本，选「多次验证」提交 5 组并查看组间变化范围。
7. 点击「运行比较」。任务逐个打开 Plant Simulation 窗口，任务表显示业务时间和计算耗时。可请求暂停、保存或取消，处理发生在事件边界。证据工具可核对直接恢复、从存档继续运行或打开恢复后的原生模型。
8. 在「比较批次」切换同一基线下的多次提交。选中某个方案后，查看结果、甘特和原生回读。通过依据抽屉回到基线、执行活动或具体工件。
9. 在已结束且有成功运行的批次点击「封存本批比较」。在「证据与回放 → 推演闭环档案」打开封存分析、回放基线或运行、登记采纳与实测。导出证据包后独立保管公钥指纹与回执。详见 [推演闭环档案](V0.2-EVIDENCE.md)。

数据源播放、原生仿真和历史回放各自有独立的暂停控制。「归档并重新载入」和「重置系统」的行为见下文。

### 校验后检查仿真模型映射

| 页面标签 | 可核对的内容 |
|---|---|
| 实例映射 | 选定工件或设备后，查看具体 ABox 节点、装载规则和对应原生位置。在加工或换型中的工件显示预计写入的 `ProcTime` |
| 字段规则 | ABox 属性、转换公式、原生写入或回读，以及控制器负责的派工和开工门槛 |
| 设备与缓冲区 | 设备标识、维护和队列状态，以及对应的原生 `Label`、`Waiting`、`Machine` 路径 |
| 工艺与设备资格 | 工序顺序、后继、标准工时、材料与精度要求、首选设备及其他设备的资格判断 |
| 工件与剩余工时 | 工件、工单、批次、基线工序、初始原生位置；加工或换型中的工件可查看剩余秒数及 `Machine.ProcTime` |
| 计划事件 | 待执行时间、优先级，以及对应的工位完工回读或唤醒事件 |

映射展示校验后的装载预览。所有方案先装载共同基线，再应用各自干预。之后的加工时长在实际派到设备时计算，Plant Simulation 的确认值见运行结果中的「原生核对证据」。

### 读结果并下钻

| 页面标签 | 适合回答 |
|---|---|
| 方案对比 | 同一统计窗口内，各方案在交付、完工、等待和在制上有多大差异？ |
| 维护影响 | 基线圈出的工件去了哪台设备、是否开工、整单能否按期交付？ |
| 交付与工单 | 哪张订单到期未完工，哪些批次或工件形成缺口？ |
| 设备与瓶颈 | 哪台设备负荷或队列最高，等待、换型、维护和共享夹具各占多少？ |
| 吞吐与物流 | 投产、完工、在制与排队怎样变化，工件经哪些路径流转？可展开趋势、分布和桑基图。 |
| 质量与返工 | 首检、复检和报废分布怎样？可以从产品下钻到检验及工件证据。 |
| 甘特与轨迹 | 按设备、工单、工件和活动筛选，查看加工、换型、维护时段；选择单件工件时还可查看排队段。 |

「维护影响」仅在方案绑定了维护异常时出现。范围在基线创建时固定，包括指派给维护设备的未完成工件，以及当前工序首选该设备、尚未投产或正在转运的相关工件。每个方案追踪这组工件的基线工序。设备去向从加工执行记录中读出，改派后仍未开工的工件保留在等待类别。

## 主数据修订

系统管理支持订单数量／批量／交期、工序工时／精度／首选设备及设备参数表单修订，也支持完整配置文件导入。点击“校验并查看差异”后查看字段差异、SHACL 结果和影响范围，再发布。发布产生新的工作空间，正在执行任务时拒绝发布，不热改旧批次。

## 备份

正常停止服务后执行：

```powershell
micromamba run -n ontologysim-v02 python -X utf8 -m scripts.v2_backup delivery/workspace-backup.zip
```

备份包含完整工作空间、账号库、已签名历史和 DPAPI 加密私钥，输出必须在数据目录外。完整账号／密钥恢复需原 Windows 用户配置；跨机器迁移分析结果使用不含私钥的证据包。不要复制仍在写入的 RocksDB 目录作为一致性备份。

## V0.1

保留 `v0.1` 标签、`app/` 与 `.runtime`。证据页可只读查看旧项目、结果和存档，明确缺少的责任主体与签名。不将旧 JSON 快照当成 V0.2 可执行本体。

旧生产配置可生成待审查草稿：

```powershell
micromamba run -n ontologysim-v02 python -X utf8 -m scripts.migrate_v01 old-spec.json new-spec-draft.json
```

同时输出 `.migration.json`，列明新增原料批次、重量和质量参数等占位假设。核对并修订后才在工作台校验发布。历史证据不补造。

## 异常处理

- “执行状态待核对”：存在未确认原生命令，不能盲目重试。保留该分支和证据，可选此前已核对的基线重新分析。
- 接入断连：订阅会重连，发布器按已提交游标重传；不完整边界不推进现场。
- 校验问题：数据与语义页展示待处理记录，修订必须保留原始来源。
- 长时间无响应：查看数据目录的 `server.stderr.log` 和系统管理的任务记录；不按进程名批量终止 Plant Simulation。
- 旧开发存档的签名覆盖率可能不完整，核验结果会显示范围；新建正式工作空间启用完整覆盖。

停止服务后也可双击 `backup.cmd`，自动生成带时间戳的新备份。重新载入会校验配置、兼容的模型摘要和轨迹完整性，通过后从来源游标零重新发布。运行 V0.1 请在独立目录检出 `v0.1` 标签并按该版文档构建前端。


## 首次载入与数据源状态

默认车间先核对随附的已验证参考轨迹，随后启动真实 MES HTTP 和 OPC UA 接入。顶部“现场数据已就绪”出现后可推进维护事件。若修改了生产配置或执行模型，需要重新生成参考轨迹；顶部显示实际计算时钟、进度、已用时间和取消入口。

“本轮现场数据已发布完毕”表示有限参考轨迹正常结束，不是连接故障。点击“归档并重新载入”会保留原工作空间和证据，再以同一生产配置创建新现场。出现失败原因时可“重试数据接入”；原生命令状态待核对时禁止盲目重试。

开发验收使用独立端口和数据目录：`python -m scripts.v2_first_load_acceptance --url http://127.0.0.1:8846`。该脚本禁止使用正式端口 8820，会归档并重建指定验收服务的工作空间。

## 可见仿真、工艺顺序与回放

- **可见仿真**：原生速度设为 100，采用非实时模式。若在意比较的等待时间，可先用 1 组配对样本筛选，再对少量候选采用 5 组验证。每组都包含基准，运行总数为「保持现状加干预数」乘以样本组数。
- **数据与语义**：ABox 业务关系和 TBox 本体结构提供可缩放节点图。颜色标识事实、事理、行动及标准概念。箭头显示方向和关系，点击查看属性或依据，双击设为焦点。默认围绕焦点展示直接关系，可筛选关系或业务层、展开邻域及反向引用。独立的「工艺顺序」视图按产品展示正常后继、首选设备、工时和返工去向。点击「执行 SHACL 校验」可查看所选版本的结果和违规对象。
- **全局图谱**：在「数据与语义」点击「全局 ABox」或「全局 TBox」。全局 ABox 可切换运行实例和溯源实例。可先按类型总览，再逐节点展开，或直接检索、分页和下载当前版本的完整 RDF。范围过大时可按类型展开。点击「刷新全局版本」可读取最新状态。
- **工位与物料流**：选择产品查看正常路线、合格工位、共享转运和返工去向。设备卡显示当前上下文的等待缓冲区与工位占用。可从队列选一件工件，按已记录的状态和位置逐步查看或播放。
- **证据与回放**：先选现场、基线或已完成方案，再逐步、拖动或播放。同一业务时刻的提交合并为一步。查看状态变化、工序、位置、设备占用和排队；点击变化行可回查对应版本。“读取最新历史”更新回放范围。
- **管理上下文**：可移除现场、基线或已结束的运行。移除现场会一并移除其基线及运行的工作台入口；单独移除基线保留已经生成的结果。正在被运行使用的上下文不能移除。
- **重置系统**：管理员在「管理上下文」打开「重置系统」，确认文字已预填，需点击「确认重置」。系统停止现场接入、关闭本应用保留的原生预览，并从工作台清空当前及历史现场、基线、任务、回放和闭环档案。重置前的档案链接和证据编号失效，操作审计从本次重置开始显示。本地账号与磁盘上的签名证据继续保留。下一次载入由用户发起。安装包不含任何运行目录或验收账号。
