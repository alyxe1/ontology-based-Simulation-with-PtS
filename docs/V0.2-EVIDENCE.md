# V0.2 证据、校验与权限

## PROV-O 映射

| PROV 概念 | 实际对象 |
|---|---|
| Entity | 原始来源、映射与工艺版本、每个生产对象的不可变版本、基线、修订、运行结果、导出清单 |
| Activity | 来源接收／对齐、运行事件、命令准备／核对、基线创建、方案执行、失败、取消、恢复、修订与导出 |
| Agent | `user/<account>` 人员；数据接入、运行服务和规则服务的软件责任主体 |
| used / qualifiedUsage | 输入对象及其当时确切版本，不依赖今后可变化的当前指针 |
| wasGeneratedBy / wasDerivedFrom | 产物对应活动、输入版本与来源 |
| wasRevisionOf / specializationOf | 历史修订与同一业务对象的不可变版本 |
| qualifiedAssociation / hadRole / hadPlan | 责任主体、执行角色与绑定策略计划 |

真实审计时间与业务时间分别保存。提交活动用带时区的 `xsd:dateTime` 表达起止时间；加工等持续活动另外保存业务起止时间。身份来自服务端会话，不接受客户端伪造 actor。实现本业务所需的身份、生成、输入版本和活动时间约束，不宣称实现全部 PROV-CONSTRAINTS 推理规则。

## 不可改写和可检测的边界

业务 API 没有删除历史或修改旧事件的接口。SourceRecord、Inspection、Mapping、Checkpoint、BusinessRevision 和 RunResult 一经提交不能覆盖。需要更正时创建新实体或新版本，并保留修订关系。

每次提交对规范化内容计算 SHA-256，连接前序摘要，再以 Ed25519 签名。被签内容包括状态变更、精确输入版本和 PROV 断言。验证器同时检查：签名、序列、前序摘要、当前状态与日志一致性、PROV 图与已签内容一致性，以及本体模式摘要。修改关系边也会失败，不只是修改 JSON 时才失败。

私钥由 Windows DPAPI 保护，保存在独立 V0.2 数据目录。导出包包含 TriG、签名记录、回执和签名文件清单；有可用原生模型时同时包含 `native.spp`。清单覆盖全部文件，拒绝重复文件名和未声明附件。

必须独立保存公钥指纹和 `receipt.json`，才能检测整条历史被替换或相对已知回执发生的截断。没有独立回执时，验证器不会把链内一致性包装成外部存证。拥有整个 Windows 用户环境控制权的管理员不在本机方案的强隔离保障范围内。

早期开发验收数据可能没有每条 PROV 断言或模式摘要的签名覆盖，验证结果会给出 `provenance_sealed_commits`、`provenance_total_commits` 和 `schema_sealed`。这些缺口不会补造为历史签名。正式版本新建工作空间完整启用上述机制。

## 离线校验

```powershell
micromamba run -n ontologysim-v02 python -X utf8 -m scripts.verify_evidence archive.zip --fingerprint <独立保存的指纹> --receipt receipt.json
```

该工具不需要 Plant Simulation 或私钥。仍需要运行环境内的 cryptography、pyoxigraph、RDFLib 依赖。退出码 0 表示检查通过；签名／内容错误会返回非零。不要把同一个压缩包中刚读取出的指纹当成独立可信指纹。

## 角色

- 管理员：账号管理和全部生产分析操作。
- 生产分析员：主数据修订、基线、方案、运行控制、证据导出。
- 审计员：查询、历史状态回放、证据核验和导出；不能创建原生任务、修改生产配置或控制数据源。

首次打开由用户创建本机管理员，没有默认生产密码。密码采用 scrypt + 随机盐；会话使用 HttpOnly、SameSite=Strict cookie，有 8 小时有效期。写操作需要应用请求标识并检查 Origin。后端仅监听 127.0.0.1。

## 回放含义

历史现场回放从签名事件重建指定版本的只读对象，不推动当前现场；分析回溯展示当时的输入、活动与结果；仿真重新执行从完整本体基线直接初始化原生模型。来源文件对应的是历史原件、差异和使用关系，不伪装成一段动画。

对象的版本是描述该对象的 Entity，通过 `os:describes` 关联业务对象。加工活动本身保持 Activity 身份，不把活动与描述它的版本记录混为同一个 PROV Entity。
