# V0.2 制造本体与标准映射

应用命名空间为 `urn:ontologysim:v2:`，软件版本为 0.2.0，运行快照的核心本体契约为 2.0。工作台本体入口版本为 2.3，通过 `owl:imports` 引用制造核心、仿真扩展、闭环证据扩展和 W3C PROV-O。标准映射范围见下表。

| 标准 / 固定参考 | 对象与实际使用 | 关系边界 |
|---|---|---|
| [IOF Core 202603](https://spec.industrialontologies.org/portal/release/202603/core.html)；版本 IRI `https://spec.industrialontologies.org/ontology/202603/core/Core/` | Equipment → `https://spec.industrialontologies.org/ontology/construct/PieceOfEquipment` | `skos:closeMatch`，不是等价类 |
| 同上 | ProductionPlan → `https://spec.industrialontologies.org/ontology/construct/PlanSpecification` | 计划信息对象的概念映射 |
| 同上 | Execution → `https://spec.industrialontologies.org/ontology/construct/PlannedProcess` | 计划执行过程的概念映射 |
| [ISA-95 / IEC 62264](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard) | Equipment、Capability、WorkOrder、Product、MaterialLot、Batch、OperationPlan | 业务对齐；未实现全部标准对象或 B2MML 交换，不虚构标准 RDF URI |
| [SOSA](https://www.w3.org/TR/vocab-ssn/) | 应用 Observation 为 `http://www.w3.org/ns/sosa/Observation` 的子类 | OPC 观测时间、设备、来源与状态；未导入整套 SSN 推理 |
| [PROV-O](https://www.w3.org/TR/prov-o/) | Entity、Activity、Person、SoftwareAgent、Plan、Usage、Association 与来源关系 | 正式继承和实际使用的属性，详见证据文档 |
| [OWL 2](https://www.w3.org/TR/owl2-overview/) / OWL-RL | 类、属性、定义域、值域、联合类、TBox 闭包 | 有限模式推理；不把资格近似映射当成真实工厂认证 |
| [SHACL](https://www.w3.org/TR/shacl/) | 分别校验制造 ABox、仿真输入和闭环证据实例 | 结合事务边界的物料与工单数量守恒、夹具容量和运行一致性校验 |
| [ISO 23247-3](https://www.iso.org/standard/78744.html) | 制造要素数字表示、现场来源、执行与服务分工 | 架构参考，不作符合性认证声明 |

事实视图表达发生了什么；事理视图表达工艺、BOM、资格和规则；行动视图表达基线、决策、方案与结果。它们是业务阅读方式，底层仍保留来源事实、推导、估计与预测的不同身份。

候选设备通过实际 SPARQL 查询：工序类型相同、材料属于资格集合、设备可达到的公差数值 ≤ 工序要求。刀具消耗、换型、夹具容量、维护与班次在确定性调度约束中参与决策。界面逐项展示匹配与拒绝原因。

## TBox、ABox 与 SHACL 文件

| 文件 | 用途 |
|---|---|
| [ontology.ttl](../ontology/v2/ontology.ttl) | 工作台本体入口；离线导入映射在 [catalog-v001.xml](../ontology/v2/catalog-v001.xml) |
| [core.ttl](../ontology/v2/core.ttl) | 制造核心类、属性、定义域和值域；运行快照在 `graph/schema` 中保存其版本 |
| [simulation.ttl](../ontology/v2/simulation.ttl) | 仿真输入词汇和业务定义，包括时钟、设备参数、工艺位置和队列 |
| [evidence.ttl](../ontology/v2/evidence.ttl) 与 [prov-o.ttl](../ontology/v2/prov-o.ttl) | 闭环档案、采纳、现场执行和改进等扩展类，以及单独保存的 W3C 来源本体 |
| [shapes.ttl](../ontology/v2/shapes.ttl) 与 [simulation-shapes.ttl](../ontology/v2/simulation-shapes.ttl) | 联合校验制造和仿真运行 ABox |
| [evidence-shapes.ttl](../ontology/v2/evidence-shapes.ttl) | 校验档案 ABox 的证据结构，在档案验证流程执行 |

TBox 图以所选版本保存的制造核心为基础，叠加当前工作台扩展，展示定义域、值域和正式类继承，包括连接到 PROV-O 的概念。通过概念索引聚焦当前邻域以外的类。ABox 图展示所选上下文的实例及关注的业务关系，推导连线使用虚线。聚焦查询每次请求最多 18 个节点，界面显示省略数量，可切换焦点、关系、业务层及展开深度。

全局 ABox 分别读取所选上下文的运行实例图和溯源实例图。全局 TBox 合并制造核心、仿真与证据扩展，以及本地 PROV-O 定义。总览按类型汇总全部引用，逐节点画布提供资源关系。属性字面值、空白节点和本体公理可通过分页三元组及完整 Turtle 文件核对。打开全局视图时固定版本，点击「刷新全局版本」获取新状态。

工艺路线中的 `os:operations` 表示产品拥有某工序，`os:next_operation` 表示正常后继。SHACL 校验同产品路线中的工序归属、顺序连续性、后继和首选设备资格。仿真输入约束进一步检查未结束工件是否指向有效工序、设备指派和位置是否一致、加工或换型中的占用与活动是否匹配，以及工件的订单、产品和原料是否与生产批次对齐。

「数据与语义」可对所选版本执行 SHACL 并定位违规对象。创建分析基线和提交方案时，后端执行同一套 ABox 校验，拒绝违规输入。方案校验预览记录规则文件及其 SHA-256；闭环档案保留封存时的本体和规则文件，便于日后核对。
