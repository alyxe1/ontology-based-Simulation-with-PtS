# OntologySim V0.2 · 生产推演工作台

OntologySim 以实例化的制造本体保存工单、批次、工件、设备、队列和待执行事件。创建分析基线后，Plant Simulation 2606 从这版状态直接装载工件和设备，运行可比较的方案。工程师可以从某个异常追到受影响工件，查看方案结果，记录现场采纳与实测，再把偏差带入下一轮模型改进。

本文对应 `v0.2-rebuild` 工作区。Git 标签 `v0.2` 指向最初的 V0.2 发布版。V0.1 的运行入口与数据说明见 [V0.1 历史文档](docs/V0.1-README.md)。

## 启动

需要 Windows、micromamba、Node.js/npm，以及可签出许可的 Plant Simulation 2606。实测版本为 **2606.0006**，COM ProgID 为 `Tecnomatix.PlantSimulation.RemoteControl.26.6`。

1. 首次部署运行 `install.cmd`。脚本创建或复用 Python 3.12 环境 `ontologysim-v02`，安装锁定的 Python 和前端依赖，构建本地页面。
2. 运行 `start.cmd`，打开 [本机工作台](http://127.0.0.1:8820)。首次使用时创建本地管理员。
3. 在「生产运行」选择「载入柔性机加工车间」。默认车间使用随附的已签名原生参考轨迹启动 ERP、MES HTTP 与 OPC UA 接入；自定义配置走原生轨迹生成流程。页面顶部显示接入准备与播放状态。
4. 使用 `stop.cmd` 正常关闭服务，再运行 `backup.cmd` 进行本机备份。部署后的页面与处理流程可离线使用，许可按本机配置工作。

V0.2 将工作空间、账号、存档与日志保存在项目下的 `.runtime-v02/`。端口、路径、备份和迁移参数见 [操作、运维与迁移](docs/V0.2-OPERATIONS.md)。

## 从维护事件走完一次推演

1. 在「生产运行」点击「推进至下一次维护开始」。到达完整接收帧后，在「异常与方案」选择该异常创建分析基线。基线固定该时刻已接收的本体版本，现场接入仍可继续。
2. 选择基线并添加干预。可采用交期优先、按资格和负荷改派、指定等待工件的合格设备，或调整每日开工时长。每批自动加入「保持现状」，方案共用统计窗口和配对样本。
3. 点击「校验方案」，再打开「查看本体 → 仿真模型映射」。选择一个工件或设备，查看其本体关系、装载规则，以及 Plant Simulation 预览中高亮的等待缓冲区或加工工位。「字段规则」等标签保留完整明细，包括初始位置、剩余时长和待执行事件。
4. 点击「运行比较」。方案串行执行，Plant Simulation 窗口保持可见。可查看正在推进的业务时钟，或在事件边界暂停、保存和取消。
5. 在「方案结果分析」比较交付、设备与瓶颈、吞吐与物流、质量返工和甘特轨迹。维护基线下可沿「维护影响」追查某件工件在哪台设备开工、是否仍在排队，以及整张工单的交付结果。
6. 点击「封存本批比较」。在「证据与回放 → 推演闭环档案」重新打开基线、分析和运行。登记采纳方案、现场执行和工单实测，按可比口径核对模拟与实际，再将改进记录关联到下一轮比较。

## 工作区

| 工作区 | 操作入口 |
|---|---|
| 生产运行 | 查看订单、批次、设备、在制工件和队列，推进到维护、控制现场数据播放或创建分析基线 |
| 产品与工艺 | 查看毛坯 BOM、工序先后、返工路径，以及材料、精度、夹具和设备资格 |
| 工位与物料流 | 查看上料、加工、转运、返工和出站路线，检查设备缓冲区，按记录回看单件工件 |
| 异常与方案 | 固定分析起点、配置和校验干预、查看本体到 Plant Simulation 的映射、比较结果与下钻 |
| 数据与语义 | 查看聚焦图和全局 ABox／TBox。全局视图支持按类型总览、逐节点展开、分页检索和 RDF 下载。聚焦视图保留关系筛选、来源查看和 SHACL 校验 |
| 证据与回放 | 查看 PROV-O 证据图谱、重开封存分析、回放历史状态、登记现场结果并校验导出包 |
| 系统管理 | 管理本地账号和角色、工作空间与基线、任务及主数据修订 |

## 当前验证范围

- 完整回归 **47 项通过**。Chrome 验证了全局 ABox/TBox、工件流转、实例映射、质量异常卡片和重置预填。双标签页验收覆盖重置后旧档案、回放链接和浏览器选中状态的清理，并实测本应用的 Plant Simulation 预览随重置关闭。启动器已实测同版本复用、旧版本空闲时重启，以及阻止更新干扰运行中或排队的任务。
- CNC01 维护基线的同一段可见原生运行，执行阶段从 **39.6 秒降至 10.5 秒**，174 个事件边界的顺序和业务终态一致。另一次完整方案以 120 件工件运行至 36 小时统计终点，从提交到结果约 **71 秒**。多方案总耗时取决于方案数、样本数和运行窗口。
- 已实测以 TriG 直接恢复加工、换型、维护、转运、夹具占用和返工边界。恢复时按剩余时间重建原生状态，业务时间通过本地原生时钟偏移接续。

默认车间提供合成数据，通过实际的本机 ERP 文件、MES HTTP 与 OPC UA 链路接入。现场实际执行和实测登记由人员完成。当前范围为受控机加工模型，预测参数尚待真实工厂校准。多零件装配、真实设备控制写回和 LLM／ASMG 融合留待后续。
